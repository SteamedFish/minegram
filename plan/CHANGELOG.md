# Changelog

All notable Minegram changes are documented here. The format follows Keep a Changelog and the project uses semantic versioning once the first playable release is tagged.

## [Unreleased]

### Added
- Added a table of localised labels for all fourteen `GameResultReason` members (`src/ui/reasonCopy.ts`), guarded by a compile-time exhaustiveness assert so a new reason cannot ship unlabelled, and a bare fallback so a machine token can never reach the player.
- Added `npm run verify:base` and a matching Pages-workflow step that statically assert every local asset in the built `index.html` resolves under the nested `/minegram/` base — the one class of breakage that works in `vite dev` and fails in production. The check is mutation-verified.

- Added a pre-generate board state with `board.empty.*` copy in both locales.
- Added a line-reveal treatment for rows and columns, and a height-aware board fit.

### Fixed
- The hint switch now actually silences the hint layer. Turning hints off removed the lit numerals and the closed-run underline but left the ✓ standing, so the loudest completion cue survived the switch that exists to remove it — the player had asked twice for this layer to be off, and a switch that relocates the complaint has not answered it. The ✓ is now withheld when the layer is off, verified present-on/absent-off in both themes through the stored flag. The contradiction badges (`✕`, `?`) deliberately stay: a line with no compatible placement is saying the marks are *wrong*, which is an error warning rather than progress feedback. The check lives in the component rather than a stylesheet rule, because a committed test cannot observe `display: none` here, and a switch whose removal cannot be asserted is a switch nobody will believe; the accessible name still reports the line's state in both phases, since for a screen reader it is the only channel there is. Also corrected a comment that claimed a run's cell window is a deduction — it is inference, read off the solution when the clue cannot force a start — and added the missing test that flipping the switch leaves every revealed mark and the whole lock array byte-identical, which had been asserted in the docs and tested nowhere.
- `--rail-digit` re-measured at the worst case a 24-cell rail can hold, 12 single-digit runs (23 of 24 cells), built by hand because the generator never produced one: a tabular figure is exactly 6.00px of advance, so the token's 6.2px leaves 2.38px of clearance, 6.0px leaves exactly none with the first numeral's left edge on the cell's content edge, and 5.3px pushes it 5.42px outside the cell. The value is unchanged and the comment now carries all three numbers, because the margin lives in the clue's own inline padding rather than in a per-digit rounding.
- Documentation and test debt found by gate `ora-7` (APPROVE WITH CHANGES, no blockers). `AGENTS.md` claimed `start`, `end` and `invariant` all report the pure deduction, which is false of `end`: when the solution pins a run's end but leaves its start free, `end` is reported and `start` stays `null`, so a non-null `end` is not a proof of position. Each field is now documented, along with the reason the renderers test `invariant` and "not exactly one of the two ends is null" together. The gate's own proposed fixture for the run-highlight fix turned out to be unconstructible — marking a cell `MINE` admits only the layout with its mine there, so the start is *forced* and the solution-window branch is never reached, which is exactly why the original defect was hard to reproduce. The fix is now pinned by the reachable shapes, including a case that fails against the pre-fix code. Two comments in the UI layer that called `mineIndices` a deduction are corrected; it is inference, and a renderer must not present it as a proof. The TODO also claimed `--rail-num` is a clamp on `--cell`; it is a flat 10px, deliberately, so the rail's width cannot feed back into the fit measurement that chooses `--cell`. The probe figures in the changelog are one-off manual measurements: `.tmp/` is gitignored, so they cannot be re-derived from the repository alone and are now labelled as such.
- Player-reported: on a small play area with many runs the clue numbers did not fit ("数字展示不全") and the game could not be played — the rails truncated by count, drawing six runs plus an ellipsis and dropping the rest. Truncation is abolished rather than capped: the column clue band is sized from the round's actual longest column clue and the row rail is a single-line, board-adjacent `max-content` track, so every run of every clue is always visible at a 10px numeral floor. Measured complete at 15×15 default fit, 15×15 in a 520×700 window (the reported configuration), and 24×24 including a 12-run stress clue, with the sticky column rail re-verified pinned. The full clue was already in every rail cell's accessible name, and with nothing ever hidden no expansion control was needed.
- Player-reported: the hint layer's on-state was a tint and a hairline. It is now a shape change — a closed run's numeral is a knocked-out digit on a solid confirm block and a closed line fills its ✓ badge strip (6.95:1 light / 6.58:1 dark measured), gated by `data-hints` on the board stage so the off-state shows the resting treatment. The screen reader keeps the full truth in both states; only presentation is gated.
- Player-reported round 2: a run's highlight needed two things the player's own rule does not ask for — a *proved* start and a separator already marked blank — so in a `7 2 2 1` column whose first three segments were placed and whose trailing `1` was still open, only the `7` lit. A run now lights as soon as every one of its mines is marked, the same condition the auto-reveal already accepted for a whole line, and its window is read off the solution when the clue cannot force a start. The two tests that asserted the stricter rule now assert this one and say why, and the player's column is a fixture of its own.
- Player-reported round 2: the live region passed `{ zoom: … }` to a template reading `{step}` in both locales, and `interpolate` copies an unmatched placeholder out verbatim, so changing the zoom announced the literal string "Zoom {step}." It survived because no test rendered the zoom branch at all. A new sweep renders every status, every transition, both locales and every toolbar note, and asserts the one property that catches the whole class: a region that has finished composing has no `{` or `}` left in it. Reverting the key fails three of its cases with the reported string in the assertion.
- Player-reported round 1: unmarked and confirmed-empty cells were too close to tell apart; the board could not grow beyond the pane and the side panels were not hideable; a completed clue carried an ugly box instead of highlighting the numeral; and the settings toggle gated editability instead of visibility. Blank cells now sit on the settled fill with a confirm border and a larger dot, the blank-locked ring is solid confirm, the fit ceiling is 56px with XL/XXL zoom steps that overflow the pane (which scrolls, sticky rail verified pinned), both side panels collapse from banner toggles whose state persists, completed runs/lines highlight the numeral itself (600 + solid underline per run, 700 + ✓ per line, box deleted), and the settings form is always editable with the banner's settings button re-opening a hidden panel and moving focus to it.
- The auto-reveal now requires at least one mine in a line. A mine-less line was vacuously eligible — every one of its cells is "marked" when none is — and was reachable in principle only because the generator guarantees a mine per line, which the reducer is not entitled to assume. Swept 48 boards across six shapes to prove it, and confirmed the reveal suite has teeth with four mutations that each break it.
- The status sentence's once-per-event guard was identity-based, and therefore always open: `projectSnapshot` re-freezes a fresh event object on every call, so `announced === lastEvent` could never hold. It now compares the four fields the sentence is derived from. The previous consequence was that the app announced nothing at all for a plain mark.
- A locale switch erased the current announcement. `publish` never assigned the closure's `lastEvent`, so `setLocale` republished `null`.
- Sentences pluralised on the wrong noun, producing "Marked 1 cells" and "The game filled 3 cell". Both reveal sentences now carry the line count and the cell count and are composed in each locale's own word order. The `Math.min(changed, autoRevealedCells)` clamp — a silent under-report — is deleted, because a line is reported only when it wrote a cell.
- The reveal was announced only for `marks-applied`, though `round/clearMark` and `round/resume` also run it.
- Refusals produced no announcement and had no printable reason. The store now publishes them with a localised label.
- A won round's banner stole focus and then destroyed it, dumping a keyboard player to the top of the document after every win. A backgrounded tab could also consume a round by elapsing the interlude.
- A first-time visitor saw "Round 0", and during the first generation two chips both read as rounds. The difficulty chip could print a raw engine reason code, the density readout echoed `mines: 0` while the draft was invalid, and the board's side bounds were hardcoded instead of read from the engine. All 225 cells carried a permanent `aria-selected="false"`.

### Changed
- A click on a locked cell is now a **deliberate silence**, documented as a ruling in `AGENTS.md` and measured in a real browser. The chain is measured, not assumed: `previewMarkBatch` skips locked cells, so an all-locked batch reports `affectedCount === 0`, and the drag controller commits only when `affectedCount > 0`, so no dispatch is ever issued. The reducer would still answer `ignored(state, 'locked-cell')` if asked, so the refusal machinery remains as defence in depth behind a correctly inert UI and is explicitly not dead code. This is the same rule as a free re-assertion: an assertion that cannot change anything says nothing.
- The win interlude is 2500ms rather than 1200ms, and it no longer elapses while the document is hidden. Auto-advance stays part of the contract; the banner's own control starts a round immediately, so waiting is a default and never a gate.
- The board fit is `Math.min` over both axes, clamped into `[24px, 44px]`, with a real `max-block-size` on the scroller. The previous `Math.max` grew a height-constrained board back out of its pane, and `max-block-size: none` meant the scroller never scrolled, so the sticky column rail resolved against a non-scrolling container. Measured: 15x15 at 1280x720 went from 150/225 cells visible to 225/225, and a 24x24 board scrolls internally with the rail pinned.

- Capped the board range at 1–24 per side (at most 576 cells) and made the settings form read `MAX_BOARD_SIDE` instead of a literal `30`. The old 25–30 range could only ever end in the typed `resource-limit` failure, so offering it was a dead end. Evidence: the binding constraint is the solver's per-line legal-pattern enumeration (10,000 patterns / 300,000 materialized cells per line), which cannot materialize a ~25-cell line with the required internal blanks. Over 25 seeds at 60% density with a 30 s budget, 24×24 recorded 0/24 failures (slowest 968 ms) while 25×25 recorded 5/24, and 26×26, 28×28, 30×30, 30×20 and 30×15 recorded 2/2, 2/2, 2/2, 2/2 and 1/2. Re-running 30×30 with `maxSolverNodes` at 400k, 1.6M and 6.4M, and with a 600 s budget, failed identically in ~350 ms with `accepted=0 rollbacks=16`, so no budget change can lift the cap — the cliff is per-line pattern materialization, not search effort. `normalizeGenerationSettings` now rejects 25×25 and 30×30 with a `RangeError` naming the new maximum, and the en/zh-CN row/column hints state `1..24` / `576`.
- Implemented the auto-reveal rule the headless win probe proved was missing. The product contract says a line whose mines are all marked shows itself automatically and a round is won once all mines are marked; the shipped `roundIsComplete` instead demanded an explicit assertion on all 225 cells and the application layer contained no reveal at all, so a player had to hand-mark 90 blanks. `revealEligibleLines` (`src/application/gameReducer.ts`) now fills every remaining cell of an eligible line as a correct, locked `blank`, free of charge, in the same commit as the batch that triggered it. Eligibility is read straight off the solution board — every mine in the line marked, and no wrong mark anywhere in it — so it needs no pattern enumeration and cannot fail closed on a resource limit. The pass never overwrites a mark, only ever writes a `blank` into a cell that is not a mine, and is idempotent: it lands on a non-mine, so it can neither complete a line nor break one, and one pass over rows then columns is already the fixpoint. The win gate moved *after* the reveal, because the batch that marks the last mine would otherwise leave every cell locked and soft-lock the round. The reveal also runs when `round/clearMark` frees a blocked line and when `round/resume` re-enters a kept board, and deliberately never in `generation/succeeded`, where a mark-less board satisfies the gate vacuously in every line and would hand over the whole board. The result now reports `autoRevealedLines` and `autoRevealedCells` so the UI can announce what the game filled. Oracle gate `ora-4` ruled the formulation first; its warning that the two entry points it was shown are not independent — on a 2×2, marking one mine also makes its column eligible, so a later mark there is refused as `locked-cell` rather than charged — is now pinned as a named test. Added `src/application/autoReveal.property.test.ts`, which certifies uniquely solvable boards with the independent reference counter and sweeps all 2⁹ and 3⁹ mark assignments per board, asserting the reveal never writes a wrong mark, never overwrites, never drops a lock, never spends a point, and is a fixed point. Two fixtures were re-sequenced instead of weakened: on a 2×2 board, marking the first mine auto-fills the rest of its row and column, so a wrong mark must be asserted before the first correct one.

- Proved the whole game loop end to end in real headless Chromium against the built `dist/` served under the nested `/minegram/` base. Two complete rounds were won by solving the 30 clues from two independent DOM sources and driving real mouse presses and drags: 135 mine cells locked and correct, zero blanks ever asserted as a mine, score 5 -> 5 -> 5, a won banner, a fresh round with different clues, and a footer showing only the authored seed. - Fixed a defect that made the status region announce the wrong thing on every mark, not only on reveals. `StatusRegion` ran a single effect that both diffed the board and advanced its own diff base, and its dependency array contained the `announced` state that the effect itself set — so the effect ran twice per commit. The first pass computed the correct delta; the self-triggered second pass then diffed the board against the base it had just stored, found no differences, and overwrote the good delta with an empty one. On the commit that closed a line the region read `You completed 1 line. The game filled 0 cell. Score 5.`; on **every plain mark with no reveal** the delta collapsed to `{cells: 0, revealedLines: 0}` and the region fell back to its resting sentence, so the game never once reported a marked-cell count. It now reads `Marked 4 cells as mines. Wrong: 0. Score 5. The game filled 3 cell in the line you completed.` and `Marked 2 cells as mines. Wrong: 0. Score 5.`, both measured in real headless Chromium. Three edits, no new component state: the announced state moved into its own effect behind a ref mirror so that no effect depends on a value it sets; the base is now *read* before it is advanced and is advanced on every publish rather than only on a commit that carries a diff, because a `mark-cleared` publish also moves marks and is not a diff — writing it only after the guard is a bootstrap deadlock in which no base is ever stored, and capturing it on the first publish instead over-credits an erased cell in the next batch; and a `diffed` ref makes the diff run exactly once per event, which is load-bearing because `setLocale` republishes the *same* event object with a freshly projected board, so board identity says nothing about whether the event is new.
- Corrected a measurement that reported the reveal as broken when it never was. `.tmp/reveal-probe.mjs` passed raw column numbers into the page function as cell indices, so it read `cell-8/9/14` in row 0 instead of the target row's `cell-83/84/89`, and its tint check compared the revealed row against `.mg-board-row[0]`, which was the revealed row itself. With an index map and a comparison against a genuinely non-revealed row, the closed line's three blanks are all `blank-locked`, the board shows exactly three `blank-locked` cells, `rowsRevealed: ["row"]` and `colsRevealed: []` — one pass, no cascade — and the previously-failing mines-only round now passes 52/52 in full. Oracle gate `ora-5` derived the invariant that made the product verdict decidable: a line is only reported when it actually wrote cells, so a reported line with a zero count is unreachable from the reducer.
